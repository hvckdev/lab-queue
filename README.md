# Очередь на сдачу лабораторных

Учебное веб-приложение, в котором студенты записываются на сдачу лабораторных работ, а преподаватель управляет очередью. Вместо списка на бумаге участники видят свою очередь в браузере.

В приложении три роли:

- **Студент** выбирает предмет и сеанс сдачи для своей группы, записывается в очередь и видит своё место.
- **Преподаватель** создаёт сеанс сдачи: указывает предмет, группу, лабораторную работу и время приёма. Затем вызывает студентов по порядку, отмечает завершение сдачи или пропускает отсутствующих. Очередь можно открыть в отдельном окне для проектора.
- **Администратор** создаёт пользователей, добавляет группы и предметы.

Серверная часть написана на Go, интерфейс — на React и TypeScript, данные хранятся в PostgreSQL 17 или новее.

## Первый запуск

Нужен установленный и запущенный Docker с Docker Compose. Отдельно устанавливать Go, Node.js и PostgreSQL не требуется.

### 1. Запустите приложение

Откройте терминал в корневой папке проекта, где находится `docker-compose.yaml`, и выполните:

```sh
docker compose up --build -d --wait
```

При первом запуске Docker скачает зависимости и соберёт приложение, поэтому это может занять несколько минут. Базы данных, таблицы и демонстрационные пользователи создаются автоматически. Файл `.env` для локального запуска не нужен.

### 2. Создайте администратора

Откройте [http://localhost:8080](http://localhost:8080). При первом входе появится форма начальной настройки. Укажите имя, свободный email и свой пароль — готового пароля администратора нет.

После создания администратора начальная настройка закрывается. Пользователи и очереди сохраняются между запусками.

### 3. Проверьте работу очереди

Выйдите из аккаунта администратора и войдите под одним из демонстрационных пользователей:

| Роль | Email | Пароль | Группа |
| --- | --- | --- | --- |
| Преподаватель | teacher@example.com | Teacher123! | — |
| Второй преподаватель | teacher2@example.com | Teacher123! | — |
| Студент | student@example.com | Student123! | ИВТ-101 |
| Студент | student2@example.com | Student123! | ИВТ-101 |
| Студент другой группы | student3@example.com | Student123! | ИВТ-102 |

Для проверки достаточно трёх действий:

1. Войдите преподавателем и создайте сеанс для группы **ИВТ-101**. Чтобы сразу начать вызов студентов, задайте начало чуть раньше текущего времени, а окончание — позже.
2. Откройте приватное окно или другой профиль браузера, войдите студентом из **ИВТ-101** и встаньте в очередь созданного сеанса.
3. Вернитесь в окно преподавателя и вызовите следующего студента. В окне студента появится вызов — очередь обновляется автоматически.

Разные окна нужны, чтобы преподаватель и студент могли работать одновременно под своими аккаунтами. Студенты также могут зарегистрироваться самостоятельно.

### Остановка и повторный запуск

Остановить приложение, сохранив данные:

```sh
docker compose down
```

Для повторного запуска используйте ту же команду, что и в первом шаге. Если приложение не открывается, проверьте состояние контейнеров командой `docker compose ps`, а ошибки — командой `docker compose logs`.

**Для полного сброса** выполните `docker compose down -v`, затем запустите приложение заново. Эта команда удалит базу данных проекта, включая пользователей и очереди.

Настройки по умолчанию предназначены для локальной демонстрации. Перед размещением в интернете нужно заменить пароли баз данных и `JWT_SECRET`, настроить HTTPS, `PUBLIC_ORIGIN` и `COOKIE_SECURE=true`.

## Архитектура и структура проекта

Приложение состоит из трёх отдельных Go-сервисов:

| Сервис | За что отвечает | Где находится |
| --- | --- | --- |
| `web` | Отдаёт интерфейс браузеру и направляет API-запросы нужному сервису | `projects/web/` |
| `accounts` | Регистрация, вход, пользователи, роли и группы | `projects/accounts/` |
| `queue` | Предметы, сеансы сдачи, запись в очередь и действия преподавателя | `projects/queue/` |

Браузер обращается только к `web`. Сервисы общаются по HTTP и передают данные в JSON. Используется один сервер PostgreSQL, но у `accounts` и `queue` отдельные базы и пользователи базы данных. Каждый сервис работает только со своими таблицами; у `web` базы нет.

### Где что находится

- `projects/web/frontend/` — исходники интерфейса на React и TypeScript. При сборке Docker собирает их и встраивает в веб-сервис.
- `projects/<сервис>/cmd/main.go` — точка запуска каждого сервиса.
- `projects/<сервис>/internal/app.go` — создание и соединение компонентов сервиса.
- `projects/<сервис>/internal/` — основной Go-код, разделённый на слои:
  - `handler/` — принимает HTTP-запросы и формирует ответы;
  - `usecase/` — описывает шаги сценариев, например регистрации или записи в очередь;
  - `service/` — содержит правила работы приложения и проверки прав;
  - `model/` — описывает данные приложения: пользователей, сеансы, записи и ошибки;
  - `adapter/` — реализует работу с базой данных и внешними зависимостями.
- `projects/accounts/internal/adapter/postgres/` и `projects/queue/internal/adapter/postgres/` — работа с PostgreSQL. Вложенные папки `migrations/` содержат изменения структуры базы, а файлы `seed.go` — начальные данные. Миграции применяются при запуске сервисов.
- `pkg/platform/` — общий код сервисов: подключения к базе, HTTP-инструменты, работа с паролями и токенами.
- `deploy/` — начальная настройка баз данных для Docker.
- `docker-compose.yaml` — сборка и совместный запуск сервисов и PostgreSQL. У каждого сервиса есть свой `Dockerfile`.
- `docs/openapi.yaml` — описание API.
- `tests/architecture/` — проверки разделения сервисов и слоёв. Тесты поведения находятся рядом с кодом сервисов.
- `Makefile` — команды для сборки, запуска и проверок. Например, `make test` запускает Go-тесты, а `make test-ui` — тесты интерфейса при установленных зависимостях.

У каждого сервиса собственный `go.mod`. Файл `go.work` в корне объединяет модули для совместной разработки. Разделение на слои позволяет менять интерфейс или способ хранения данных, не смешивая эти изменения с правилами работы очереди.
